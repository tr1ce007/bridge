# THE BRIDGE

Платформа, которая помогает подросткам, студентам и взрослым понять, куда двигаться. Три языка: русский (по умолчанию), казахский и английский. Светлая и тёмная тема.

Этот файл для команды проекта. Если что-то непонятно, пишите вопросы в общий чат.

## 1. Что это

THE BRIDGE помогает исследовать варианты через три вещи:

- **свои ответы** (анкета и личный отчёт);
- **настоящие истории людей**, которые меняли путь;
- **маленькие эксперименты**: попробовать направление за один вечер, а не гадать годами.

Внутри есть ИИ-собеседник «Давай разберёмся».

Принципы, на которых всё построено:

- Сайт **ничего не предсказывает**. Нет фраз вроде «тебе суждено стать юристом». Отчёт это набор гипотез, которые можно проверить делом.
- Мы **не выдумываем** истории, цифры, дедлайны и стипендии. Если факта нет, так и пишем: «уточняйте на официальном сайте» или «источник уточняется».
- Вымышленные примеры **всегда подписаны**: «Демонстрационный пример (вымышлен)». У каждой истории есть бейдж: проверенный источник, публично задокументировано, от пользователя или демо.
- Без ключей сайт **честно работает в демо-режиме** и всегда показывает пометку «ИИ не подключён».
- Личные данные по умолчанию лежат **только в браузере** человека. Их можно скачать и стереть в «Настройках».
- Никакие истории не публикуются сами: всё проходит через модератора.

## 2. Что уже работает (без всяких ключей)

Мы прошли весь путь руками в браузере 18.11.2026 в локальном режиме (без Supabase и без ИИ). Вот что сработало:

- Главная страница на русском, казахском и английском. Переключение языка на любой странице сохраняет ту же страницу.
- Светлая и тёмная тема, мобильная версия (проверяли на ширине 375 px).
- Анкета `/explore`: адаптивные вопросы по правилам, ответы сохраняются сами, можно закрыть вкладку и вернуться.
- Отчёт `/report/...` в демо-режиме: собирается алгоритмом по ответам, с направлениями, похожими историями и планом на 7, 30 и 90 дней.
- Сохранить историю, сохранить направление, править шаги плана.
- «Попробуй, прежде чем выбрать» `/try`: эксперименты, отметка «Я сделал(а)», размышление после эксперимента.
- Истории `/stories`: фильтры, страница истории, форма отправки. Отправка честно отвечает, что без базы данных она не работает (код 503).
- Возможности `/opportunities`: фильтры, сохранение.
- Чат `/chat` в демо-режиме: отвечает, что ИИ не подключён, и даёт полезные ссылки.
- Кабинет `/dashboard`: прогресс, сохранённое, план, прошлые отчёты, «Как менялись мои мысли».
- Дневник `/journal`, сравнение двух отчётов `/compare`, «А если я попробую?» `/what-if` (в демо-режиме по правилам).
- «Спроси человека» `/mentors`: форма интереса (хранится только на устройстве).
- Настройки `/settings`: скачать свои данные (один файл JSON) и удалить всё, с двойным подтверждением (нужно напечатать слово УДАЛИТЬ).
- Страницы `/about`, `/privacy` и красивая страница 404.
- `/auth` и `/admin` честно говорят, что нужна настройка Supabase.
- Сборка (`npm run build`) проходит, главные страницы отвечают кодом 200 на `npm run start`, автотесты проходят.

## 3. Что требует ключей и настройки

| Что подключить | Что оно открывает | Пока не подключено |
|---|---|---|
| **Supabase** (база данных) | Вход по ссылке из письма, хранение данных в аккаунте на разных устройствах, админка, отправка историй людьми, жалобы на истории, список сбоев ИИ и анонимная статистика | Всё хранится в браузере, `/auth` и `/admin` показывают инструкцию, отправка историй и жалобы отвечают 503 |
| **ИИ** (Anthropic или OpenAI) | Настоящий отчёт, уточняющие вопросы в анкете, живой чат, «А если я попробую?» от ИИ, выделение полей истории в скрипте поиска | Демо-режим: правила вместо ИИ, везде видна пометка |
| **Вход через Google** | Кнопка «Войти через Google» | Кнопки нет, остаётся вход по ссылке из письма (нужен Supabase) |
| **Reddit** | Скрипт `npm run discover` ищет истории на Reddit | Скрипт работает только с RSS-лентами |

Важно: **Supabase, ИИ и Reddit мы ни разу не пробовали вживую** (у нас не было ключей). Логика покрыта тестами с «ненастоящими» заменами, но первый запуск с настоящими ключами нужно пройти аккуратно (см. раздел 10).

## 4. Как запустить локально

Нужен Node.js. Проверено на Node 26, скрипт поиска историй использует возможности Node 20.12 и новее.

```bash
cd the-bridge
npm install
cp .env.example .env.local     # можно оставить пустым: сайт заработает в демо-режиме
npm run dev                     # откройте http://localhost:3000 (он сам перейдёт на /ru)
```

Другие команды:

```bash
npm test         # автотесты
npm run lint     # проверка кода
npm run build    # боевая сборка
npm run start    # запустить собранный сайт (после build)
npm run discover # поиск историй (раздел 8)
```

Папка проекта лежит в iCloud (Рабочий стол). iCloud создаёт копии файлов вида «файл 2.ts» и ломает сборку. Поэтому результат сборки идёт не в `.next`, а в **`.next.nosync`** (iCloud пропускает папки, которые заканчиваются на `.nosync`). Это настроено в `next.config.ts`, ничего делать не нужно. Старую папку `.next` мы не трогали, её можно удалить самим, когда решите.

## 5. Переменные окружения

Файл `.env.local` (его нет в git). Образец: `.env.example`. Без них сайт работает в демо-режиме.

| Переменная | Что делает | Обязательна? |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Адрес проекта Supabase (Project settings → API). Если заданы обе переменные `NEXT_PUBLIC_SUPABASE_*`, включается режим Supabase | Нет. Нужна для базы, входа и админки |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ Supabase. Его можно видеть в браузере, данные защищает RLS | Нет. Нужна вместе с адресом |
| `SUPABASE_SERVICE_ROLE_KEY` | Секретный ключ, обходит защиту RLS. Только сервер. Нужен для записи сбоев ИИ и аналитики и для `npm run discover -- --insert`. Никому не показывать | Нет. Нужна для админ-списка сбоев, статистики и вставки историй скриптом |
| `AI_PROVIDER` | Какой ИИ отвечает: `anthropic`, `openai` или `demo`. Пусто = выбрать самому: Anthropic, если есть его ключ, иначе OpenAI, иначе демо. Если назвали провайдера без ключа, будет демо | Нет |
| `ANTHROPIC_API_KEY` | Ключ Anthropic (только сервер) | Нет. Нужен для ИИ от Anthropic |
| `ANTHROPIC_MODEL` | Какая модель Anthropic. По умолчанию `claude-sonnet-5-5` | Нет |
| `OPENAI_API_KEY` | Ключ OpenAI или совместимого сервиса (только сервер) | Нет. Нужен для ИИ от OpenAI |
| `OPENAI_BASE_URL` | Адрес совместимого API, например `https://api.openai.com/v1`. Пусто = адрес по умолчанию | Нет |
| `OPENAI_MODEL` | Название модели для OpenAI-совместимого провайдера | Нет. По умолчанию `gpt-4o-mini` |
| `NEXT_PUBLIC_GOOGLE_AUTH_ENABLED` | `true` показывает кнопку «Войти через Google». Сначала включите Google в Supabase | Нет. По умолчанию `false` |
| `REDDIT_CLIENT_ID` | Идентификатор приложения Reddit для `npm run discover` | Нет. Нужен только для поиска на Reddit |
| `REDDIT_CLIENT_SECRET` | Секрет приложения Reddit (только скрипт) | Нет. Нужен вместе с идентификатором |
| `RATE_LIMIT_PER_MINUTE` | Сколько запросов к ИИ в минуту на одного посетителя и одну страницу. По умолчанию 10 | Нет |

Переменные с `NEXT_PUBLIC_` попадают в браузер, поэтому в них только то, что не секрет. Секретные ключи (`SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `REDDIT_CLIENT_SECRET`) никогда не кладите в `NEXT_PUBLIC_` и не отправляйте в git.

## 6. Настройка базы данных (Supabase)

1. Зарегистрируйтесь на supabase.com и создайте проект.
2. Выполните миграции из папки `supabase/migrations` **по порядку**: `0001_init.sql`, `0002_try_stories_opportunities.sql`, `0003_dashboard_journal_directions.sql`, `0004_auth_admin.sql`.
   - Самый простой путь: Supabase → SQL Editor → вставить файл → Run, по очереди все четыре.
   - Или через Supabase CLI (`supabase link`, потом `supabase db push`). Этот путь мы не проверяли.
3. Затем выполните `supabase/seed.sql` (демо-истории, эксперименты и возможности). Он создан скриптом из `src/content/*.json`, руками его не правьте. Если поменяли JSON, обновите файл командой `node scripts/build-seed.mjs`.
4. Authentication → Providers: включите **Email** (вход по ссылке из письма).
5. Authentication → URL Configuration: поставьте адрес сайта (Site URL) и добавьте в Redirect URLs адрес `<адрес сайта>/auth/callback`. Для работы на своём компьютере добавьте ещё `http://localhost:3000/auth/callback`.
6. По желанию включите **Google**: Authentication → Providers → Google, вставьте Client ID и Secret из Google Cloud, а в Google Cloud добавьте тот адрес возврата, который покажет Supabase. После этого поставьте `NEXT_PUBLIC_GOOGLE_AUTH_ENABLED=true`.
7. Впишите три ключа Supabase в `.env.local` (раздел 5) и перезапустите сайт.
8. **Как стать админом.** Сначала войдите на сайт по ссылке из письма (так создастся ваш профиль). Потом в SQL Editor выполните:

   ```sql
   update public.profiles set role = 'admin' where id = '<ваш id>';
   ```

   Ваш id виден в Authentication → Users. Роли: `user` (по умолчанию), `moderator`, `admin`. Сменить роль можно только так (из SQL) или админом, сам человек себе роль поднять не может.

Миграции нужно запускать по одному разу и по порядку (0001 нельзя запускать повторно: таблицы уже будут созданы; 0004 написана так, что её повторный запуск безопасен). Сначала попробуйте всё на тестовом проекте.

## 7. Настройка ИИ

1. Получите ключ на сайте провайдера: Anthropic (console.anthropic.com) или OpenAI (platform.openai.com). Вход в консоль и оплата на вашей стороне.
2. Впишите его в `.env.local`: `ANTHROPIC_API_KEY=...` (или `OPENAI_API_KEY=...`) и перезапустите `npm run dev`.
3. Проверка: откройте `http://localhost:3000/api/ai/status`. Должно быть `{"demo":false,"provider":"anthropic"}`.

Модель: по умолчанию `claude-sonnet-5-5`. Чтобы сменить, впишите `ANTHROPIC_MODEL=название-модели`. Для OpenAI-совместимого сервиса задайте `OPENAI_MODEL` и при необходимости `OPENAI_BASE_URL`. Какой провайдер выбран, определяет `AI_PROVIDER`.

**Без ключа** сайт работает в демо-режиме: анкета идёт по правилам, отчёт собирается алгоритмом, чат отвечает «ИИ не подключён» и даёт ссылки. Пометка «демо-режим» видна всегда.

**Если ИИ сломался** (ошибка, долгий ответ, неправильный формат), сайт не падает: показывает отчёт по правилам с пометкой, а сбой записывается (в таблицу `ai_failures`, если подключён Supabase; смотреть в `/admin/ai-failures`).

**Ограничение частоты:** по умолчанию 10 запросов в минуту на посетителя и страницу (`RATE_LIMIT_PER_MINUTE`). Счётчик хранится в памяти сервера (см. раздел 9).

## 8. Поиск историй

Скрипт ищет открытые истории людей, которые меняли путь, и готовит **черновики для проверки людьми**. Он ничего не публикует сам.

Откуда берёт:

- **Reddit** через официальный API (нужны `REDDIT_CLIENT_ID` и `REDDIT_CLIENT_SECRET`; приложение создаётся на reddit.com/prefs/apps).
- **RSS/Atom-ленты** из таблицы `story_sources` (добавляются в `/admin/sources`) или из локального файла `scripts/sources.json` (образец: `scripts/sources.example.json`; сам файл в git не попадает).

Как запустить:

```bash
npm run discover                 # результат: scripts/out/discovered-<дата>.json (не попадает в git)
npm run discover -- --insert     # то же + положить черновики в Supabase как «на проверке»
npm run discover -- --help       # все параметры
```

Что важно знать:

- Скрипт читает `robots.txt` у сайтов с лентами и **не заходит туда, куда нельзя**. Не больше одного запроса в секунду к одному сайту, есть тайм-аут. Перенаправления он проходит сам, не больше трёх, и для каждого нового адреса снова смотрит `robots.txt` и ждёт свою секунду.
- Reddit может притормаживать или блокировать запросы с общим названием программы (`the-bridge-story-discovery/0.1`). Если так случилось, скрипт напишет об ошибке и пропустит Reddit.
- Для каждой находки он пишет: ссылку на источник, название источника, автора (открытый ник или «anonymous»), дату, если известна, и **короткую выдержку до 500 символов** (из уважения к авторским правам). Не целый текст.
- Каждый черновик это `kind: documented`, `status: pending`. Если подключён ИИ, он дополнительно вытащит из текста поля «что было раньше», «трудности», «поворотный момент», «действия», «что сейчас» и теги. Тексты из интернета передаются ИИ как данные, а не как команды. То, чего в тексте нет, остаётся пустым и помечается как неполное. Ничего не додумывается.
- Скрипт не притворяется, что работает. Если нет ни одного источника (нет ключей Reddit и нет лент), он пишет, чего не хватает, и выходит с ошибкой, ничего не записав. Если нет только Reddit, он ищет в лентах и пишет, что Reddit пропущен. `--insert` без Supabase тоже сразу выходит с понятной ошибкой.
- **Всё идёт на модерацию.** Заметки для проверяющих (например, «ИИ: похоже, это не личная история») лежат только в JSON-файле, в поле `notes`: смотрите их там перед одобрением. Черновики, которые ИИ счёл «не личной историей», с `--insert` **не вставляются**, они остаются только в файле. С `--insert` истории попадают в Supabase как «на проверке», и модератор одобряет их в `/admin` (раздел «Истории»). Повторный запуск не создаёт дубли: каждая история получает номер по адресу источника.
- Перед одобрением проверьте: источник по ссылке, имя автора, нет ли в тексте личных данных. Перед боевым использованием Reddit прочитайте условия Reddit Data API и убедитесь, что вам разрешено так использовать записи.
- Команда `npm run discover` запускает `tsx --conditions=react-server ...`. Флаг нужен, чтобы слой ИИ (он помечен «только для сервера») запускался вне Next.js.

Скрипт мы проверили без интернета (автотесты на готовых файлах) и на своём локальном сервере с лентой (с `robots.txt`). **Настоящий Reddit и вставку в настоящий Supabase мы не проверяли.**

## 9. Деплой

Подойдёт Vercel (или любой хостинг для Next.js).

1. Подключите репозиторий к Vercel.
2. Впишите **все нужные переменные окружения** в настройках проекта (раздел 5). Без них там будет демо-режим.
3. В Supabase добавьте адрес боевого сайта в Redirect URLs (`<сайт>/auth/callback`).
4. Ограничение частоты запросов к ИИ хранится **в памяти каждого экземпляра сервера**. На Vercel их может быть несколько, и после перезапуска счётчик обнуляется. Это мягкая защита от случайных циклов, а не настоящая защита от злоупотреблений. Для настоящей защиты нужно общее хранилище (например Upstash Redis).
5. Счётчик определяет посетителя по заголовку `x-real-ip`, который ставит прокси или платформа. Разворачивайте сайт **за прокси, который его ставит** (Vercel ставит его сам; в nginx для этого нужна строка `proxy_set_header X-Real-IP $remote_addr;`). Без такого прокси заголовки может подделать любой.

## 10. Текущие ограничения

Это честный список. Мы собрали его из отчётов по всем этапам работы.

**Проверка и перевод**

- Казахский и английский текст написан нами и **нуждается в проверке носителем**. Больше всего вопросов к казахским подписям фильтров и типов возможностей. Имя основателя на казахском это транслитерация.
- Описания партнёров («Команда, из которой вырос проект») выведены из сертификата. Покажите команде.

**Не проверялось вживую**

- Настоящие вызовы Supabase и ИИ ни разу не проверялись. Логика покрыта тестами с заменами. Миграции 0003 и 0004, вход по ссылке, Google и все страницы админки не запускали на настоящем проекте.
- Для Anthropic в коде включён запасной режим моделей (`fallbacks: "default"`). Если настоящий API его не примет, **каждый отчёт молча станет демо-отчётом** (в журнале сбоев будет запись `report:http`). Поэтому первый запуск с ключом проверьте глазами.
- Вставка найденных историй скриптом и вход в Reddit не пробовались на настоящих сервисах.

**Контент**

- Статистика «44% подростков не знают, кем хотят стать» показана с пометкой «источник уточняется»: источник не найден. Пока его нет, держите эту пометку. Для «более 30% выпускников работают не по специальности» источник есть (заявление вице-министра труда, tengrinews.kz), но это данные по колледжам и вузам вместе.
- Историй пока только **демонстрационные (вымышленные)** и подписаны так. Проверенных реальных историй нет, пока вы их не добавите и не проверите по ссылке.
- У возможностей **нет дедлайнов** (везде «уточняйте на официальном сайте»), а **стоимость в основном неизвестна**, поэтому фильтр «бесплатно» узкий. Уровни (бакалавриат, магистратура) в нескольких записях взяты из общих знаний, а не со страниц: просмотрите их глазами. UN Volunteers не открылся при проверке, он помечен как непроверенный. Нет записей про стажировки, конференции, конкурсы и менторство.
- Официальное название программы не переводится (в базе одно поле `name`).

**Функции**

- Заявки на наставников («Спроси человека») **хранятся только на устройстве**, даже у вошедших в аккаунт: таблицы для них пока нет. Живых наставников на платформе нет, выдуманных профилей тоже.
- **Удаление аккаунта идёт через команду**: в настройках человека просят написать вам, но **контактного адреса команды в продукте пока нет**. Его нужно добавить (мы не придумывали).
- Отметка «Начал(а) эксперимент» хранится только на устройстве, даже в режиме Supabase. Результаты экспериментов синхронизируются.
- В чате помнится только последний разговор. Сообщение человека сохраняется после ответа, поэтому при закрытии вкладки посреди ответа последний ход теряется. Есть мелкие известные недочёты вокруг согласия на память (например, очистка при выключении согласия может не сработать, если сохранить настройку не удалось). Они не критичны, но их стоит исправить до больших тестов с людьми.
- Идентификатор сохранённого направления это номер по порядку в отчёте. Пока отчёты не редактируются, это безопасно.
- События «анкета пройдена» и «отчёт собран» считаются на сервере на каждый запрос: повторная сборка отчёта засчитывается снова.
- Данные гостя при первом входе предлагается перенести в аккаунт (есть код и тесты), но настоящий вход мы не проверяли.
- Согласие автора на публикацию проверяется на сервере и записывается временем (`consent_at`), но юридически это не заменяет согласие по правилам вашей страны. Покажите текст юристу.
- На странице истории блок «Люди, похожие на меня» всегда предлагает пройти анкету, даже если она уже пройдена. Это мелкая неточность текста.
- Страница `/report/<неизвестный id>` отвечает кодом 200 и показывает пустое состояние (отчёты берутся из браузера, сервер их не знает).
- Фильтры историй не попадают в адрес страницы (нельзя поделиться ссылкой с фильтром).

**Среда разработки**

- В режиме `npm run dev` ненайденная история сначала отвечает кодом 200 с красивой страницей «404» (так работает потоковая отрисовка). В боевой сборке код правильный, 404. В dev в консоли при показе 404 есть предупреждение про `<script>`: в боевой сборке его нет.
- Казахские даты (например «2026 ж. 18 қараша») в окне браузера внутри приложения Claude показались как «2026 M11 18»: у него нет данных казахской локали. В Node они форматируются правильно. Перепроверьте в настоящем Chrome и Safari.
- Если окно браузера скрыто, первый показ страницы в dev может «висеть» на «Загружаем…». Это особенность скрытого окна, а не сайта.

the-bridge/

  src/
    app/[locale]/      страницы сайта (главная, explore, report, chat, try, stories, opportunities, dashboard, journal, compare, what-if, mentors, settings, about, privacy, auth, admin)

    app/auth/callback  возврат после входа по ссылке и Google
    components/        интерфейс по разделам (landing, explore, report, chat, dashboard, admin и др.) и общие кирпичики (ui)

    lib/
      ai/              слой ИИ: провайдеры, подсказки, защита от prompt injection, ограничение частоты

      report/          схема отчёта, каталог направлений, отчёт по правилам

      data/            хранилище: локальное и Supabase, типы, экспорт

  docs/superpowers/    дизайн проекта и план работ
